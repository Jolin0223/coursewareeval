## Rules — apply every time

### 1. viewport meta (in `<head>`)
```html
<meta name="viewport" content="width=device-width, initial-scale=1.0, maximum-scale=1.0, user-scalable=no">
```

### 2. html / body CSS
```css
html, body \{
    width: 100\%;
    height: 100\%;
    overflow: hidden;
    margin: 0;
    padding: 0;
\}
```

### 3. `#app` container — the 1920×1080 canvas
All visible content lives inside `<div id="app">`. Its CSS must be:
```css
#app \{
    position: absolute;
    top: 50\%;
    left: 50\%;
    width: 1920px;
    height: 1080px;
    transform-origin: center center;
    /* JS will set: transform: translate(-50\%, -50\%) scale(<s>) */
    visibility: hidden;
    /* JS will set: visibility: visible; */
    overflow: hidden;
\}
```
Do **not** hardcode a `transform` in CSS — the JS function owns that property.

### 4. Scaling JS — required in every page
Place this script block before `</body>` (or in the JS file that runs on load):
```js
(function () \{
    var app = document.getElementById('app');
    function updateScale() \{
        var s = Math.min(window.innerWidth / 1920, window.innerHeight / 1080);
        app.style.transform = 'translate(-50\%, -50\%) scale(' + s + ')';
        app.style.visibility = 'visible';
    \}
    window.addEventListener('resize', updateScale);
    updateScale();
\})();
```

### 5. Layout coordinates
Design all child elements with **pixel values** relative to the 1920×1080 canvas (e.g. `position: absolute; left: 60px; top: 50px`). Never use `vw` / `vh` / `\%` of the viewport for internal layout — those units do not scale correctly inside the fixed canvas.

## 交互约束
请在实现所有点击、触摸、拖拽、滑动、长按等交互时，尽量统一使用 Pointer Events：
  - 优先使用 pointerdown、pointermove、pointerup 和 pointercancel
  - 避免使用 click、mousedown、mousemove、mouseup、touchstart、touchmove 和 touchend
  - 拖拽开始后使用 setPointerCapture(pointerId)，结束或取消时释放
  - 对图片等浏览器默认可拖拽的元素实现自定义拖拽时，必须关闭原生拖拽，优先设置 draggable="false"，避免桌面 Chrome 的原生图片拖放中断 Pointer Events
  - 根据需要通过 pointerType 区分 mouse、touch 和 pen
  - 拖拽时记录当前 pointerId，只处理对应指针；对于 mouse，当 buttons === 0 时必须立即停止拖拽，同时处理 lostpointercapture 和窗口失焦，避免松开鼠标后元素仍然跟随
  - 正确处理多点触控、指针移出元素、组件卸载和 pointercancel
  - 防止同一次操作被重复触发
  - 及时移除事件监听器并清理交互状态；拖拽结束或取消后按规则落位或复位，保证下一次操作可开始
  - 非当前状态的弹层、遮罩及其全部子元素不得接收点击或拖拽，不能仅设置opacity为0，避免拦截当前可用按钮
  - 根据交互需求合理设置 CSS touch-action
  - 仅在确有必要时调用 preventDefault()
生成代码时，请主动检查现有的鼠标、触摸及点击事件；能够安全替换的，统一改用 Pointer Events。仅在 Pointer Events 无法满足需求时保留其他事件，并在注释中说明原因。

## 数据上报运行时要求
生成的 HTML/JS 代码必须通过 window.kpmSdk 完成数据上报：
1. 游戏开始时调用 kpmSdk.startGame() 记录 startTime；
2. 游戏完成时调用 kpmSdk.reportGameResult(metrics) 一次性上报，metrics 为指标编码到值的映射对象；
3. 上报失败不得阻断游戏流程。

## 字体使用规范
1. 英语游戏
- 英文字体（单词场景）：
  - 默认：`Heinemann Roman`（常规） / `Heinemann Bold`（加粗）
  - 指定人教版或人教手写体：`Italic Adjust`；同时指定四线三格：`Italic JX Four Four Adjust`。
  - 指定苏教版或苏教手写体：`shuangyu-SU`（常规）；同时指定四线三格：`shuangyu-SU-line`。
  - 指定cake印刷体或cake系列：`EnglishCake`（常规）；同时指定四线三格：`EnglishCake4Line`。
  - 字体系列与四线三格同时出现时优先选择对应系列四线字体；仅指定四线三格而未指定系列时，沿用`Italic JX Four Four Adjust`。字体名称必须与`https://iteachcdn.xdf.cn/mmcw/font/fontVar.css`的font-family一致，不使用不存在的`English cake`别名。
  - 中文字体或阿拉伯数字（仅限必要场景）：`方正准圆简体`（常规） / `方正粗圆简体`（加粗），需要拼音注音的文字除外。
2. 非英语游戏
默认字体：`方正准圆简体`（常规） / `方正粗圆简体`（加粗），需要拼音注音的文字除外。
3. 拼音内容
凡需要为汉字显示拼音注音时，HTML中只输出汉字原文，并对该段汉字整体使用`方正楷体拼音字库01`，由字体自身同时呈现拼音和汉字，不得单独生成或渲染拼音文本。严禁使用独立拼音、拼音数组、JS拼音转换、伪元素或手动空格实现拼音；不得将拼音和汉字拆成上下两层。注音文本应保留足够行高，避免字体自带拼音被裁切。未配置拼音的标题、按钮、说明和其他普通文字仍按对应学科的默认字体规则处理。

## 功能按钮组件与低幼视觉落地
需要常用功能按钮时，在对应代码任务中明确引用`https://iteachcdn.xdf.cn/mmcw/icon.css`及所需`cb-icon-*`类、主题、位置、真实动作和状态切换，复用已提供的组件清单，不生成这些图标的图片任务或重新绘制SVG。通用教学插图、Logo等仍按原素材规则处理。相关代码任务须包含所需类名和调用说明，不假设下游自动获得本段上下文；沿用现有taskDetails与输出协议。
方案明确低幼风格时，将饱满轮廓、背景/内容/控件层级、适度轻拟物和操作区域安排落实到相关素材或布局任务；已有文字完整、学科字体和舞台缩放规范优先，不扩大无关装饰。
