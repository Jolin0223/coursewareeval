# 完成操作按场景保留｜待研发确认

基于上一轮“按钮文案分场景”的完整九份TXT修订；本次取消的是多余确认，不是禁止所有“完成”语义。候选尚未部署服务端提示词或复测。

| 场景 | 规则 |
| --- | --- |
| 单题或当前步骤重试 | 英文用Retry，仅重试当前题或步骤 |
| 最终结果弹窗整轮重玩 | 英文用Try again，从第一题开始，重置本轮进度与成绩 |
| 完成结果已展示 | 不额外添加Done/完成二次确认 |
| 绘画、搭建、录音等无法判断何时结束，或确需确认最终作答 | 保留必要结束/提交入口，优先“画好了”“搭好了”“结束录音”“提交答案”等准确动作文案；英语用对应英文，需表达“我做完了”时可用I’m done |
| 仅标记已完成 | 使用非交互状态标签，不伪装成按钮 |

用户明确指定优先；语言仍遵循课件规范。任务不涉及这些操作时，不因为列举而新增。

## 开发确认与部署

替换prompts目录九份完整TXT。方案设计判必要性；创建架构师拆解文案、触发与动作；修改架构师限定本轮范围；生成、审查和修复按用途判断，不仅凭Done/完成字样删按钮。单文件修复能力、输出结构、SDK字段、封面与字体规则均保持原样。

本轮不改CSS或manifest，也不在提示词包中附带图标资源，避免覆盖研发单独更新的图标版本；无需重新上传CDN。恢复说明已有cb-icon-done的按需用途，不把它当成必须生成的按钮。Retry与Try again继续复用cb-icon-retry。历史HTML不批量改动。

字体缺失已确认是资源未上传，不作为本次提示词问题。上轮12例测试不代表本候选已通过；部署后验证单题重试、整轮重玩、必要主动结束、非交互完成标签与无多余Done确认这几类场景。
