# 按钮自适应与圆润反馈图标 2.2.1候选

先打开index.html评审。当前仅本地候选，未修改业务CDN与服务端系统提示词。

## 本轮改动

- cb-text由固定248px改为width:max-content，min-width:248px；左右28px、图文间距16px。高度按内容，最小92px。图标和文案不收缩；普通纯图标按钮不变。
- 新增答对correct、答错incorrect、实心star、轮廓star-empty四个状态。正误采用圆头粗笔画，星星外尖和内角均用曲线。绿色/红色背景仅为默认反馈配色，可覆盖变量。
- 已确认加入：提示hint、画笔pencil、橡皮擦eraser、撤销undo。保持原16个图标路径，合计24个；新增图标可通过cb-icon-*调用。
- 反馈用cb-feedback、cb-feedback-symbol或cb-stars展示，不使用button模拟无动作状态。需由调用方提供可见文案或aria-label，不只靠颜色表达结果。
- 星星数量、评分门槛、正误反馈是否出现由玩法决定，不由CSS决定。主题图像式反馈仍可按需求生成。

## 提示词候选（待确认后再落入各环节）

文字按钮复用组件时保留按内容自适应宽度，不覆盖为固定width；按实际字体、最长文案与图标检查两侧留白，空间不足时优先调整本区布局，不压缩图标或裁切文字。

仅当教学规划需要正误判断或星级反馈时，优先复用对应圆润图标；不因库中有图标而新增判分、星级或奖励流程。展示方式、星星数量和反馈文案按用户意图与实际玩法决定；明确要求其他形式或主题需要定制时可采用相应素材，保持清楚、圆润和风格一致。提示、画笔、橡皮擦、撤销同样按已规划功能选用。

## 开发更新顺序

1. 本页确认视觉与宽度，再用新版本资源在测试环境接入；模型使用新类名之前，先保证CSS已上传。
2. 新生成代码不得用固定width覆盖自适应；父布局也不能强制压缩按钮。图标CSS解决默认值，不能覆盖任意课件中的高优先级错误样式。
3. 原始16类名不变，但覆盖原CDN地址会改变旧课件中动态引用的文字按钮宽度；本地打包旧CSS的课件不自动升级。先验证28例回归及长按钮布局，再决定是否覆盖原地址或按版本迁移。不会自动重新生成旧HTML。
4. 不把截图或DOM测试当作实屏跨端验证。须在Chrome137及其他实际支持端检查CSS mask、字体加载、舞台缩放、长文案和交互。

baseline-icon.css是本次读取的线上基线，changes.diff可核对差异；svg目录提供8个新增SVG源文件，icon.css已内嵌，无需额外请求SVG。manifest是开发清单，不是运行依赖。页面字体只供本地评审使用，不改变平台字体打包策略。
